DungeonKit

A free and open-source trainer and companion app for Minecraft Dungeons and Minecraft Dungeons II. It works by reading and editing the game's memory in real time while you play, similar to a Cheat Engine table but packaged into a proper app. It also includes extra features like a built-in console and more, all in one convenient app so you don't need multiple tools to manage everything.

View source on GitHub

What it does

DungeonKit connects to your game while it's running, letting you toggle switches, edit values, and monitor live stats. Features include currency editing, difficulty adjustments, item stats, player tools, a free camera, an on-screen overlay, and much more - all without directly modifying your save files or requiring a second tool running alongside it.

DungeonKit automatically detects which game and build you're running, supporting Steam, the Microsoft Store/Xbox app, and the Minecraft Launcher. It then adapts its available features to match your game version and update, ensuring compatibility with the build you're playing.

(Assuming the game's next update doesn't break something first.)

Build it yourself

Install Qt 6 (or Qt 5.15+), Visual Studio 2022 (or MinGW) and CMake, then either run Build-DungeonKit.bat from the project folder, or:

cmake -S . -B build -DCMAKE_PREFIX_PATH="C:/Qt/6.7.0/msvc2019_64"
cmake --build build --config Release

Full build and usage steps are in the repository's README. Click a command above to copy it.

Built with

C++17 Qt 6 Widgets CMake MinGW / MSVC

A significant portion of DungeonKit, at least for Minecraft Dungeons, works by editing the game's memory, much like a traditional Cheat Engine table. However, most of its newer features leverage Unreal Engine's built-in reflection system.

Rather than relying on hardcoded memory addresses, DungeonKit can locate properties by name at runtime using property offsets. This makes it more resilient to game updates than a typical fixed-offset trainer.

As a result, DungeonKit can potentially continue working across multiple game versions, even when it hasn't been explicitly updated, thanks to the information it can access at runtime. In some cases, this allows it to effectively adapt to newer builds without requiring a dedicated update for every release.
